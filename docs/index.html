moonhttp

The HTTP family for MoonBit: the formats a request and a response are written in, each a package of its own. Bytes in, events out; no sockets.

$moon add moonbitstack/moonhttp

@url

RFC 3986 URI references: taking one apart, putting it back, resolving a relative one, and percent coding by component.

enum
enum Kind {
  /// Unreserved only — everything else is escaped. This is what one piece of a
  /// query goes out as, since `&` and `=` inside a value must not read as the
  /// separators they look like.
  Bare
  /// `reg-name` (§3.2.2): unreserved and sub-delims.
  Host
  /// `userinfo` (§3.2.1): `reg-name` and `:`.
  Userinfo
  /// One `segment` (§3.3): `pchar`, so `/` is escaped and stays one segment.
  Segment
  /// A whole `path` (§3.3): `pchar` and `/`.
  Path
  /// `query` (§3.4): `pchar`, `/` and `?`.
  Query
  /// `fragment` (§3.5): the same set as `query`.
  Fragment
  /// A whole URI reference: everything the grammar allows anywhere, `%`
  /// included. What a `Location` header carries — the value is already a URI,
  /// and only the octets no URI may contain need escaping.
  Whole
} derive(Eq, Debug)

Which component an octet is going into, and so which octets may stand for themselves (RFC 3986 §2.2, §3). & is ordinary inside a path and a separator inside a query. The grammar answers that, not the caller.

let
let kind : Kind = Bare

The strictest component, for when nothing says. Escaping an octet that did not need it changes nothing; leaving one that did changes where the component ends.

struct
struct Url {
  scheme : String?
  userinfo : String?
  host : String?
  port : Int?
  path : String
  query : String?
  fragment : String?
} derive(Eq, Debug)

A URI reference taken apart (RFC 3986 §3). No scheme makes it relative (§4.2). No host means no authority, which is not an empty host — file:///tmp has one, mailto:x@y has none. Fields stay percent-encoded. Decoding on the way in would lose the difference between a / that separates two segments and a %2F inside one.

suberror
suberror Refused {
  /// A port that is not digits, at this offset.
  Port(at~ : Int)
  /// An IP-literal with no closing bracket, at the opening one's offset.
  Host(at~ : Int)
} derive(Eq, Debug)

Why a string is not a URI reference. Only the authority can fail: §B splits any string at all into the five top-level components, and does not split that one.

fn
fn escape( raw : BytesView, kind? : Kind = kind, spare? : StringView = ""[:]) -> String

Percent-encode octets for kind (RFC 3986 §2.1). Octets, not text: what travels inside a URI is whatever the caller encoded it as. [escape_text] is the one that assumes UTF-8. spare is for percent coding that is not going into a URI at all — gRPC's grpc-message keeps all of printable ASCII but %, which is no component of RFC 3986's. A URI component names its kind and leaves spare alone.

fn
fn escape_text( text : StringView, kind? : Kind = kind, spare? : StringView = ""[:]) -> String

Percent-encode text as UTF-8 (RFC 3986 §2.5).

fn
fn unescape(raw : BytesView) -> Bytes

Undo percent-encoding (RFC 3986 §2.1). A % without two hex digits after it stands for itself. This runs on request targets and form bodies, where refusing the whole message over one stray % helps nobody; [escaped] is for the caller who would rather be told.

fn
fn unescape_text(text : StringView) -> String

Undo percent-encoding and read the result as UTF-8, replacing what is not.

fn
fn escaped( text : StringView, kind? : Kind = kind, spare? : StringView = ""[:]) -> Bool

Whether every % is a complete escape and nothing outside kind's set is there unescaped — the check [unescape] does not make.

fn
fn normalize_escapes(text : StringView) -> String

Percent-encoding normalised (RFC 3986 §6.2.2.2): hex digits in upper case, and escapes of unreserved octets written out plainly.

fn
fn Url::decode(text : StringView) -> Url raise Refused

Take a URI reference apart (RFC 3986 §3, by the split §B states). Any string splits, so what comes back is a reference even when it is one nobody would write. Only the authority can be malformed.

fn
fn Url::new( scheme? : String, userinfo? : String, host? : String, port? : Int, path? : String = "", query? : String, fragment? : String) -> Url

A reference this shape, for building one rather than reading one.

fn
fn Url::encode(self : Url) -> String

Put the reference back together (RFC 3986 §5.3).

fn
fn Url::authority(self : Url) -> String?

The authority as one string, brackets restored around an IP-literal (§3.2).

fn
fn Url::is_absolute(self : Url) -> Bool

A reference with a scheme and no fragment is a URI (§3); anything else is a relative reference or a same-document one.

fn
fn Url::resolve(self : Url, reference : Url) -> Url

Resolve reference against this base (RFC 3986 §5.2.2, strict). Strict: a reference that repeats the base's scheme stays absolute. The non-strict reading is for pre-1998 parsers and turns http:g into something it does not say.

fn
fn remove_dots(path : String) -> String

Take out the . and .. segments (RFC 3986 §5.2.4). The section's loop rather than a split-and-rejoin: the two differ at exactly the inputs that matter — a trailing .., a path that climbs above its own root, /..//.

fn
fn Url::normalize(self : Url) -> Url

Syntax-based normalisation (RFC 3986 §6.2.2): scheme and host to lower case, escapes normalised, dot segments out. Not §6.2.3: dropping :80 is true of http and false in general, and this package holds no register of schemes.

The first file under this name.

fn

Every field, in the order they were sent.

fn
fn Form::uploads(self : Form) -> Array[Upload]

Every file, in the order they were sent.

fn
fn Form::is_empty(self : Form) -> Bool

Whether anything was parsed at all.

struct
struct Limits {
  parts : Int
  part_size : Int
} derive(Eq, Debug)

What a form is allowed to be. A body arrives from whoever sent it, so both bounds are needed: a million empty parts and one enormous part are different ways of asking a server to allocate more than it has.

let
let limits : Limits =

A thousand parts of a megabyte each — what Starlette's max_files and max_fields default to, with python-multipart's part size. Generous for a form and far from what exhausts a server. A caller that knows its own shape should say so.

fn
fn Limits::new( parts? : Int = limits.parts, part_size? : Int = limits.part_size) -> Limits

Build a bound by naming the parts that differ from the default. The same thing can be written { ..@mime.limits, parts: 8 }; this form reads better when several parts differ. There is no per-call mirror of these two. A bound belongs to an endpoint rather than to a request — an avatar upload and a spreadsheet import are two endpoints, each with its own — so the record is the only place it comes from, and there is nothing to arbitrate.

suberror
suberror Refused {
  /// More parts than allowed.
  Parts(limit~ : Int)
  /// One part longer than allowed.
  Part(limit~ : Int, got~ : Int)
  /// A multipart body that stops making sense at this offset. Only raised under
  /// `strict`; otherwise the parts read so far are returned.
  Malformed(at~ : Int)
  /// A content type that is neither form encoding. Only raised under `strict`;
  /// otherwise the answer is an empty form.
  NotAForm(content_type~ : String)
} derive(Eq, Debug)

Why a body was not read as a form. A form over its bounds is refused whole rather than truncated: a handler given the first thousand parts of a larger form would be answering a request nobody sent.

fn
fn parse( body : BytesView, content_type : StringView, limits? : Limits = limits, strict? : Bool = false) -> Form raise Refused

Parse a body by what its Content-Type says it is. A content type that is neither form encoding yields an empty form rather than an error: "this request carried no form" is an answer, not a failure, and a caller asking for a form on a JSON request wants to hear that. strict is for the caller who would rather be told.

fn
fn urlencoded( body : BytesView, limits? : Limits = limits) -> Form raise Refused

Parse an application/x-www-form-urlencoded body (the WHATWG URL standard's form-urlencoded parsing). + is a space here and nowhere else in a URL, which is the one thing about this encoding everybody gets wrong.

fn
fn multipart( body : BytesView, boundary : StringView, limits? : Limits = limits, strict? : Bool = false) -> Form raise Refused

Parse a multipart/form-data body (RFC 7578) given its boundary. A part goes into the files when its Content-Disposition carries a filename and into the fields when it does not, which is the only thing distinguishing them on the wire.

fn
fn param(header : StringView, key : StringView) -> String?

A parameter out of a header value: name from form-data; name="file"; filename="a.txt". A quoted value ends at the closing quote; a bare one at the next semicolon.

fn
fn boundary(content_type : StringView) -> String?

The boundary of a multipart/form-data content type.

@dataurl

RFC 2397 data URLs: a whole representation written inside the reference to it.

let
let kind : String = "text/plain;charset=US-ASCII"

What a data URL means when it names no media type (RFC 2397 §2).

struct
struct Url {
  /// The media type with its parameters, as the URL spells it.
  kind : String
  /// The payload.
  data : Bytes
} derive(Eq, Debug)

A data URL taken apart: what the octets are, and the octets (RFC 2397 §3). data is already decoded. Which of the two spellings the URL used is a property of the text, not of what it carries.

suberror
suberror Refused {
  /// It does not begin with `data:`.
  Scheme
  /// Nothing separates the header from the payload (§3 requires a comma).
  Comma
  /// A `%` with fewer than two hex digits after it. Only under `strict`.
  Escape(at~ : Int)
  /// The payload is not base64, at this offset into it.
  Base64(at~ : Int)
} derive(Eq, Debug)

Why a string is not a data URL.

fn
fn Url::new(data : Bytes, kind? : String = kind) -> Url

A data URL carrying these octets.

fn
fn Url::charset(self : Url) -> String

The charset the payload's text is in (RFC 2397 §2). US-ASCII when nothing says otherwise, which is the default media type's own parameter rather than a guess of ours.

fn
fn Url::encode(self : Url, base64? : Bool = true) -> String

Write the URL out. base64 defaults on, as webpack's asset modules do (generator.dataUrl.encoding). Turn it off for SVG and anything else a human may want to read in the URL. A media type equal to [kind] is left out; reading one back puts it there again.

fn
fn Url::decode( text : StringView, strict? : Bool = false) -> Url raise Refused

Read a data URL. strict turns the two things browsers let pass into errors: base64 with whitespace or the wrong padding, and a % that is not an escape. Left off, a lone % stands for itself and whitespace is dropped.

@media

RFC 9110 media types and RFC 6266 Content-Disposition — what a body is, and what to save it as.

let
let fallback : String = "application/octet-stream"

What a response says it is when nothing says otherwise. application/octet-stream is what RFC 9110 §8.3 names for "some bytes, and I am not going to guess" — a browser offers to save it rather than trying to render it, which is the safe answer for content of unknown shape.

fn
fn type_of(filename : StringView) -> String

The media type a filename's extension implies. Deliberately short. This labels the downloads that actually occur; it is not a copy of the IANA registry, and a caller that knows the type names it rather than hoping the extension does. The text types carry charset=utf-8, because a browser handed text/plain with no charset applies its own locale's and shows something else.

fn
fn disposition(filename : StringView, inline? : Bool = false) -> String

The Content-Disposition value naming filename (RFC 6266). A name that survives percent-encoding unchanged is quoted as it is; anything else — a space, an accent, a quote, a newline — goes out as filename*, which is the only form that can carry a character outside ASCII and the only one that cannot be made to end the header early. inline asks the browser to display the content rather than save it, which is what a PDF or an image served for viewing wants.

@range

RFC 9110 §14 range requests: the fields, the arithmetic against a length, and the multi-range body.

let
let unit : String = "bytes"

The only range unit HTTP defines (RFC 9110 §14.1.2). It is a parameter everywhere rather than a constant because §14.1 leaves the registry open, and a reader that hard-coded bytes would silently mis-handle a unit it was never told about instead of ignoring it.

let
let limit : Int = 200

How many ranges one request may ask for before the answer is to send the whole thing instead (RFC 9110 §14.2). A request may name any number of ranges, and a server that honours all of them does a great deal of seeking for one client — the shape of the 2011 Apache range attack. 200 is Apache's own MaxRanges default.

enum
enum Spec {
  /// `first-last`: both positions, inclusive.
  Between(Int64, Int64)
  /// `first-`: from here to the end, however long it turns out to be.
  From(Int64)
  /// `-suffix`: the last so many octets.
  Last(Int64)
} derive(Eq, Debug)

One range as a client asked for it, before it is measured against a length (RFC 9110 §14.1.1). The three shapes are the grammar's: an int-range with both ends, an int-range with only a first position, and a suffix-range. They stay separate because they mean different things — From(0) asks for everything, while Last(0) asks for nothing and is unsatisfiable.

struct
struct Part {
  at : Int64
  last : Int64
} derive(Eq, Compare, Debug)

One range measured against a representation: the first and last octet, both inclusive (RFC 9110 §14.1.2). Inclusive because the field is, and converting at the edge is where off-by-one errors come from. [Part::length] gives the count for a caller who wants one.

fn
fn Part::length(self : Part) -> Int64

How many octets this part covers.

fn
fn decode(value : StringView, unit? : String = unit) -> Array[Spec]?

Read a Range field value (RFC 9110 §14.2). None means the field is to be ignored, which §14.2 requires for a unit the server does not implement and for a value that does not parse. Ignoring it is not an error: the answer is the whole representation, with status 200. An empty range-set is not a range request either — bytes= names no range, and serving everything is the right reading of it.

fn
fn encode(specs : ArrayView[Spec], unit? : String = unit) -> String

Write a Range field value (RFC 9110 §14.2).

fn
fn measure( specs : ArrayView[Spec], length~ : Int64, merge? : Bool = true, limit? : Int = limit) -> Array[Part]?

Measure what was asked against a representation of length octets (RFC 9110 §14.1.2). None is unsatisfiable, and the answer to it is 416 with the [unsatisfied] Content-Range — not 200, and not an empty 206. A request is unsatisfiable only when *no* spec in it is satisfiable; §14.1.1 says one good spec carries the field, and the ones that cannot be met are dropped. merge coalesces ranges that overlap or touch, which §14.2 permits and which keeps bytes=0-100,50-150 from sending the middle twice. limit caps how many ranges survive; past it the caller should send the whole representation, so exceeding it reads as "no ranges here" rather than as an error.

struct
struct Content {
  unit : String
  part : Part?
  complete : Int64?
} derive(Eq, Debug)

A Content-Range field value (RFC 9110 §14.4): where a part sits in the whole, or — in a 416 — only how big the whole is. part is absent in the */complete form a 416 carries. complete is absent in the part/* form, which says the total length was not known when the field was written.

fn
fn Content::new( part : Part, complete? : Int64, unit? : String = unit) -> Content

The Content-Range of a part that was served (RFC 9110 §14.4). complete is the length of the whole representation. Leaving it out writes *, which §14.4 reserves for a sender that does not know the total — a generated response being streamed, say. Give it when it is known: a client recombining parts needs it.

fn
fn unsatisfied(complete : Int64, unit? : String = unit) -> Content

The Content-Range a 416 carries: bytes */1234 (RFC 9110 §14.4). It names no part because there is none to name; the number is what the client needs in order to ask again for something that exists.

fn
fn Content::encode(self : Content) -> String

Write a Content-Range field value (RFC 9110 §14.4).

fn
fn Content::decode(value : StringView) -> Content?

Read a Content-Range field value (RFC 9110 §14.4). None is a value that cannot be trusted, and §14.4 is explicit about what follows: a recipient must not recombine content with a stored representation on the strength of an invalid Content-Range. So a last position before the first, or a complete length that does not reach past the last position, is refused here rather than repaired.

fn
fn accept(ranges? : Bool = true, unit? : String = unit) -> String

The Accept-Ranges field value (RFC 9110 §14.3). none is not the absence of the field: it says outright that range requests will not be honoured, which stops a client from trying and failing.

fn
fn multipart(boundary : StringView) -> String

The Content-Type a multi-range 206 carries (RFC 9110 §14.6).

fn
fn parts( parts : ArrayView[(Part, Bytes)], boundary~ : String, kind~ : String, complete? : Int64, unit? : String = unit) -> Bytes

The body of a multi-range 206 (RFC 9110 §14.6): one part per range, each with its own Content-Type and Content-Range, then a closing boundary. parts pairs each range with its octets — this package does no reading, so the caller fetches them. kind is the representation's own media type, which §14.6 repeats in every part because each part is a document in its own right.

@conditional

RFC 9110 §8.8 and §13: entity-tags, the five precondition fields, and the order §13.2.2 weighs them in.

struct
struct Tag {
  text : String
  weak : Bool
} derive(Eq, Debug)

An entity-tag (RFC 9110 §8.8.3). text is what is inside the quotes; keeping them would put the field's syntax inside the value. weak is the W/ in front. Two weak tags mark representations that are equivalent, not identical — enough for "has this changed", not enough for "may I splice these two ranges".

enum
enum Tags {
  Any
  These(Array[Tag])
} derive(Eq, Debug)

What a precondition field names (§13.1.1): every representation, or these tags. * is not a tag that matches everything. §13.1.1 and §13.1.2 both read it as "does a representation exist", and answer in opposite directions.

enum
enum Validator {
  Marked(Tag)
  Dated(@moondate.Moment)
} derive(Eq, Debug)

Either kind of validator (§8.8). If-Range takes one or the other (§13.1.5); the other four fields each take one kind.

enum
enum Verdict {
  /// No precondition failed: carry on with the method.
  Go
  /// The client's copy is still good — 304, with no body (§15.4.5).
  Fresh
  /// A precondition failed — 412 (§15.5.13).
  Failed
} derive(Eq, Debug)

What §13.2.2 says to do with the request once the preconditions are weighed.

fn
fn Tag::new(text : String, weak? : Bool = false) -> Tag

A tag with this text.

fn
fn Tag::same(self : Tag, other : Tag) -> Bool

Strong comparison (§8.8.3.2): neither is weak and the texts match. If-Match and If-Range use this one — both are about replacing or splicing octets, which a weak tag does not promise.

fn
fn Tag::alike(self : Tag, other : Tag) -> Bool

Weak comparison (§8.8.3.2): the texts match, weakness ignored. If-None-Match uses this one — a weak tag can answer "has it changed".

fn
fn hash( raw : BytesView, digest~ : &@spec.Hash, weak? : Bool = false) -> Tag

An entity-tag from the octets themselves: their count and their digest, both in hexadecimal. Strong, which is the point of hashing the content. digest is a parameter — which hash to spend on every response is the server's trade. The shape is the etag package Express serves static files with, "<length>-<digest>", in nginx and Apache's hexadecimal.

fn
fn stamp( length~ : Int64, modified~ : @moondate.Moment, weak? : Bool = true) -> Tag

An entity-tag from what a file system knows without opening the file: when it last changed and how long it is. nginx's "<mtime>-<length>", one stat. Weak, as a one-second timestamp must be: two writes inside the same second leave both numbers unchanged.

fn
fn Tag::encode(self : Tag) -> String

Write the tag as a field value: "x", or W/"x" (§8.8.3).

fn
fn Tag::decode(text : StringView) -> Tag?

Read one entity-tag. None when it is not one — usually an unquoted value, which §8.8.3 has no room for.

fn
fn Tags::encode(self : Tags) -> String

Write a whole field value: *, or the tags separated by commas.

fn
fn Tags::decode(text : StringView) -> Tags?

Read a whole field value. Commas are found outside the quotes: , is in the etagc set (§8.8.3), so a tag may contain one. None when any member is not an entity-tag — §13.1.1 has no reading for half a list.

fn
fn Validator::decode(text : StringView) -> Validator?

Read an If-Range value (§13.1.5). The first two characters tell them apart, as §13.1.5 says: only an entity-tag starts with a quote, only a weak one with W/.

fn
fn Validator::encode(self : Validator) -> String raise @moondate.Refused

Write an If-Range value. Raises for a moment with no zone — an HTTP-date is GMT by definition (§5.6.7).

struct
struct Ask {
  /// `If-Match` (§13.1.1).
  matching : Tags?
  /// `If-None-Match` (§13.1.2).
  none_matching : Tags?
  /// `If-Modified-Since` (§13.1.3).
  modified_since : @moondate.Moment?
  /// `If-Unmodified-Since` (§13.1.4).
  unmodified_since : @moondate.Moment?
  /// `If-Range` (§13.1.5).
  ranging : Validator?
} derive(Eq, Debug)

The five precondition fields of one request (§13.1), already read.

let
let ask : Ask =

A request that carried no preconditions at all.

fn
fn Ask::new( matching? : Tags, none_matching? : Tags, modified_since? : @moondate.Moment, unmodified_since? : @moondate.Moment, ranging? : Validator) -> Ask

The preconditions a request carried, named one at a time.

fn
fn Ask::read(headers : ArrayView[(String, String)]) -> Ask

Pull the five fields out of a request's headers. Names match without regard to case (§5.1). Two lines of one list-valued field are one list (§5.3), so the tag fields are joined before reading; the date fields are not lists, so a repeat is ignored. A field present but unreadable comes back absent, per §13.1.3 and §13.1.4.

fn
fn Ask::evaluate( self : Ask, verb~ : String, etag? : Tag, modified? : @moondate.Moment, present? : Bool = true) -> Verdict

Weigh the preconditions in the order §13.2.2 sets out. verb is the request method (method is reserved). It decides what a failed If-None-Match means: 304 for a GET or HEAD, 412 otherwise. No default — guessing GET would tell a PUT its copy is current. etag and modified are what the server holds; present is whether it holds anything at all, which is all * asks.

fn
fn Ask::unchanged( self : Ask, etag? : Tag, modified? : @moondate.Moment) -> Bool

Whether If-Range still holds, and so whether a Range may be honoured (§13.1.5). Absent holds: no condition, nothing in the way. Both kinds compare strongly, and a weak tag is refused rather than compared — "may these octets be spliced onto yours" is what a weak tag may not answer.

@cookie

RFC 6265 Cookie and Set-Cookie, each read and written.

enum
enum SameSite {
  Strict
  Lax
  Unrestricted
} derive(Eq, Debug)

How far a cross-site request may carry a cookie. Strict sends it only on a same-site request, Lax also on a top-level navigation, and Unrestricted sends it everywhere. Unrestricted is the wire value None, spelled differently here because None is the empty option; a browser honours it only on a Secure cookie.

fn
fn SameSite::code(self : SameSite) -> String

The attribute's wire spelling.

fn
fn SameSite::of(text : StringView) -> SameSite?

The attribute a spelling names, or None for one no revision defines. The comparison ignores case, as §5.2 says to do with every attribute value.

struct
struct Cookie {
  name : String
  value : String
  /// When the cookie dies, written as the HTTP-date `Expires` carries.
  expires : @moondate.Moment?
  /// How long it lives, in seconds. A browser that understands it prefers it to
  /// `Expires`, which is why a deletion writes both.
  max_age : Int?
  domain : String?
  path : String?
  secure : Bool
  http_only : Bool
  same_site : SameSite?
} derive(Eq, Debug)

One cookie, as Set-Cookie states it. An attribute left None is left out of the header, and means what leaving it out means: no Expires and no Max-Age is a session cookie, no Domain is the origin host alone, no Path is the request's own directory.

fn
fn Cookie::new( name : String, value : String, expires? : @moondate.Moment, max_age? : Int, domain? : String, path? : String? = Some("/"), secure? : Bool = false, http_only? : Bool = false, same_site? : SameSite? = Some(Lax)) -> Cookie

A cookie by name, with the defaults a server usually wants. path defaults to /, so the cookie covers the whole site, and same_site to Lax, which is what a browser assumes of a cookie that does not say — and what stops a cross-site form post from carrying a session. Passing None for either leaves the attribute out.

fn
fn Cookie::encode(self : Cookie) -> String

The Set-Cookie field value this cookie is sent as. Attributes come in RFC 6265 §4.1.1's order, which is the order a browser and a log reader expect. The octets a name, value, domain or path may not carry are dropped rather than escaped: what a reader gets back is then the text that was set, and a \r\n smuggled into a value cannot open a header of its own. An expires that is a time with no date aborts: a cookie cannot die at a clock reading, and a caller that built one has made a mistake rather than met a condition.

fn
fn Cookie::decode(raw : StringView) -> Cookie?

The cookie a Set-Cookie field value states, or None when it states none — an empty field, or one whose first pair has no =. Everything §5.2 says to ignore is ignored rather than refused: an attribute no revision defines, an Expires that is not a date, a Max-Age that is not a number.
